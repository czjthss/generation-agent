# generation-agent

[English](README.md) | [中文](README.zh-CN.md)

`generation-agent` is a LangChain-based, multi-agent time-series generation system exposed through a CLI, a web UI, and an MCP server. It turns a natural-language request such as:

```text
Generate the summer electricity load of an industrial park in southern China
```

into synthetic time-series data saved as compact Arrow files. The goal is not to fit or copy existing data, but to use domain knowledge, feature families, semantic constraints, anomaly logic, and deterministic validation to generate plausible series.

## Highlights

- Natural-language generation with a fixed multi-agent workflow.
- Component-based mechanism modeling: a variable can be decomposed into baseline, cycles, events, operating windows, environmental effects, and other components.
- Feature-family generation instead of domain-specific hardcoding.
- Output semantic handling for cumulative totals, stock-flow processes, random walks, regime switching, saturation growth, decay/recovery, and multivariate lag effects.
- Optional reference Arrow profiling: statistics are extracted locally and used as generation priors without sending raw observations to the LLM.
- Dataset mode for generating many diverse scenarios under one broad domain.
- Compact Arrow output for large generated datasets.
- Web UI with parameter controls, output-folder selection, reference Arrow upload, and preview plots.
- MCP server for external clients.

## Project Structure

- `generation_agent/features.py`: generic feature families such as cycles, trends, sparse events, daylight envelopes, smooth environmental signals, count processes, bounded utilization, noise, and anomalies.
- `generation_agent/component_workflow.py`: componentized workflow that turns high-level mechanisms into component-level feature plans.
- `generation_agent/planner.py`: converts a natural-language request into a structured `SeriesPlan`.
- `generation_agent/planning_prompts.py`: prompt templates for profiling, scenario design, component mechanism modeling, feature planning, and quality evaluation.
- `generation_agent/capability_registry.py`: builds a runtime pipeline capability manifest from installed constants, function signatures, and source AST for anomaly strategy, deterministic validation, and quality evaluation.
- `generation_agent/langchain_agent.py`: LangChain tool-calling workflow and LLM-based quality review.
- `generation_agent/dataset_scenario_agent.py`: creates diverse concrete scenarios for dataset mode.
- `generation_agent/dataset_diversity.py`: checks and scores diversity across generated dataset scenarios.
- `generation_agent/reference_profiler.py`: extracts statistical and structural profiles from reference Arrow series.
- `generation_agent/synthesizer.py`: deterministic numerical synthesis, component composition, semantic transforms, anomalies, and validation.
- `generation_agent/semantic_transforms.py`: cumulative, stock-flow, random-walk, regime-switching, decay/recovery, saturation-growth, and lag mechanisms.
- `generation_agent/semantic_validators.py`: monotonicity, bounds, integer, cumulative identity, and conservation checks.
- `generation_agent/compact_storage.py`: Arrow writing and preview sampling.
- `generation_agent/web_app.py`: Flask web UI.
- `generation_agent/mcp_server.py`: MCP server tools.
- `generation_agent/cli.py`: command-line interface.

## Installation

```bash
conda create -n generation-agent python=3.11 -y
conda activate generation-agent
cd generation-agent
pip install -r requirements.txt
```

Create a local `.env` file from the example:

```bash
cp .env.example .env
```

Then edit `.env`:

```text
OPENAI_API_KEY=your_api_key_here
OPENAI_BASE_URL=https://api.openai.com/v1
GENERATION_AGENT_MODEL=gpt-5.5
GENERATION_AGENT_COST_MODE=balanced
```

Shell environment variables take precedence over values in `.env`.

## CLI Usage

Generate one Arrow series:

```bash
python -m generation_agent.cli "生成中国南方夏季工业园区的电力负载" \
  --generation-mode sequence \
  --length 168 \
  --output outputs/load.arrow
```

Generate a dataset from a broad domain:

```bash
python -m generation_agent.cli "气象" \
  --generation-mode dataset \
  --series-count 20 \
  --length 720 \
  --output-dir outputs/weather_dataset
```

Dataset mode writes per-series `.arrow` files, `manifest.json`, and `scenarios.json`. It does not rely on an existing dataset; scenarios are generated by the LLM and then synthesized through the same planning and generation pipeline.

Use `--cost-mode cheap|balanced|strict` to control context and retry budget. `balanced` is the default. `cheap` minimizes retry budgets while preserving LLM planning, anomaly strategy, and quality evaluation. `strict` keeps the larger reflection and regeneration budget for final validation. All LLM calls still use the single `--model`; split-model routing is intentionally not enabled.

Use a reference Arrow series:

```bash
python -m generation_agent.cli "生成同类工业负载" \
  --reference reference_load.arrow \
  --length 1000 \
  --output outputs/synthetic_load.arrow
```

The reference profiler extracts distribution, trend, autocorrelation, candidate periods, sparsity, and event-duration statistics locally. Raw observations are not copied into prompts.

## MCP Server

Start the MCP server:

```bash
python -m generation_agent.mcp_server
```

Main tools:

- `plan_time_series(description, model=None)`: returns a structured generation plan.
- `generate_time_series(...)`: generates time-series data directly.
- `generate_time_series_code(...)`: returns standalone Python generation code.

## Workflow

```text
User request / parameters / optional reference Arrow
  -> Requirement Understanding Agent
  -> Mechanism Planning Agent
  -> Parameter Compilation Agent
  -> Anomaly Strategy Agent
  -> Local Generation Kernel: component synthesis, composition, semantic transforms, validation, and repair
  -> Quality Evaluation Agent
       -> revise and regenerate when a hard failure is grounded
       -> accept when consistent
  -> Arrow Output + manifest + scenario metadata
```

The system uses LLMs for domain understanding, mechanism design, feature parameterization, anomaly decisions, and quality evaluation. Local deterministic code performs numerical synthesis, storage, validation, and repair.

## Feature Families

The tools are organized by time-series feature families rather than a fixed list of domains:

- `cyclic_signal`: electricity load, water demand, regular usage signals.
- `intermittent_event`: rainfall, faults, outages, and other sparse events.
- `daylight_envelope`: photovoltaic generation and solar irradiance.
- `smooth_environmental`: temperature, water temperature, and inertial environmental signals.
- `count_process`: traffic, orders, API requests, passenger flow.
- `bounded_utilization`: CPU usage, memory usage, occupancy, utilization rates.

The LLM maps domain knowledge to feature-family parameters. For useful new domains, it can save reusable custom rules in `domain_rules.json`.

## Output Semantics

The agent separates the base signal generator from the mathematical meaning of the output:

- `instantaneous`: ordinary point observations.
- `cumulative`: nondecreasing totals, generated from nonnegative increments.
- `stock_flow`: state updated by inflow and outflow.
- `regime_switching`: state-dependent behavior such as on/off/fault modes.
- `random_walk`: drift plus random steps, useful for prices or exchange rates.
- `decay_recovery`: shock followed by decay or recovery.
- `saturation_growth`: growth toward a capacity limit.
- `multivariate_lag`: driver variables with lagged effects.

The LLM decides which semantic mechanism and constraints should apply. Deterministic validators then check monotonicity, bounds, conservation, integer constraints, and related invariants.

## Anomaly Control

The anomaly interface is intentionally compact:

```bash
# Let the LLM decide
python -m generation_agent.cli "生成工业园区电力负载" --anomalies auto

# Disable anomalies
python -m generation_agent.cli "生成工业园区电力负载" --anomalies off

# Force high-severity anomalies
python -m generation_agent.cli "生成累计销售额" \
  --anomalies on \
  --anomaly-severity high
```

Severity presets:

- `low`: fewer, shorter, smaller anomalies.
- `medium`: moderate anomaly count, width, and magnitude.
- `high`: more frequent, stronger, and longer anomalies.

When anomalies are enabled or implied by the prompt, the LLM decides where they should act: increments, flows, random-walk steps, component signals, states, or final observations.

## Python API

```python
from generation_agent import AnomalyOverrides, GenerationAgent

agent = GenerationAgent()
df = agent.generate(
    "生成累计销售额",
    length=168,
    anomaly_overrides=AnomalyOverrides(
        enabled=True,
        severity="high",
    ),
)
```

## Output Columns

Common columns:

- `timestamp`
- `value`
- `anomaly`

Depending on the semantic type, generated data may also include:

- `increment`
- `inflow`, `outflow`, `net_flow`
- `state`
- `step`
- `impulse`
- `growth_rate`
- `driver`, `lagged_driver`

Arrow metadata and dataset manifests store domain, unit, generator type, semantic type, cost mode, component workflow, compact planning evidence, anomaly strategy, deterministic validation, quality evaluation, scenario definitions, and preview information. The LLM plans and audits; concrete numeric values are computed by the local numerical generation kernel.
